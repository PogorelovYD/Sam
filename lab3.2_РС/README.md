## 📚 Теоретические сведения

### Обнаружение отказов

Обнаружение отказов является важной задачей в распределённых системах.  
Если один из узлов выходит из строя, остальные узлы должны узнать об этом за приемлемое время.

Для обнаружения отказов могут использоваться разные подходы:

- периодическая проверка доступности узлов;
- обмен служебными сообщениями;
- распространение информации между узлами;
- случайная проверка соседей.

---

### Gossip-протокол

Gossip-протокол работает по принципу распространения слухов.  
Каждый узел периодически выбирает несколько случайных соседей и передаёт им известную информацию.

Преимущества Gossip:

- хорошая масштабируемость;
- отсутствие необходимости проверять все узлы напрямую;
- постепенное распространение информации по сети;
- устойчивость к частичным потерям сообщений.

Недостатки:

- время сходимости зависит от параметров сети;
- возможны задержки при распространении информации;
- результат зависит от `fanout`, `interval`, потерь пакетов и задержек.

---

### Heartbeat Full-mesh

Heartbeat — это подход, при котором узлы периодически проверяют доступность других узлов.

В реализации Full-mesh каждый живой узел проверяет все остальные узлы.

Преимущество:

- быстрое обнаружение отказов.

Недостаток:

- очень большой сетевой трафик при росте количества узлов.

---

### Ping Random Probe

Ping Random Probe — это подход, при котором каждый узел проверяет одного случайного соседа.

Преимущество:

- минимальная нагрузка на сеть.

Недостаток:

- медленная сходимость;
- не все отказы быстро обнаруживаются всеми узлами.

## 🧮 Этап 1. Расчёт полосы пропускания

Для теоретического расчёта нагрузки Gossip-протокола была реализована функция:

```python
def calculate_bandwidth(nodes, fanout, packet_size_bytes, interval):
    messages_per_second = nodes * fanout / interval
    bandwidth_bps = messages_per_second * packet_size_bytes * 8
    return bandwidth_bps
```

Формула расчёта:

```text
Bandwidth = (Nodes × Fanout / Interval) × PacketSize × 8
```

где:

| Параметр | Описание |
|---|---|
| Nodes | количество узлов |
| Fanout | количество соседей, которым отправляется сообщение |
| Interval | интервал рассылки |
| PacketSize | размер одного сообщения в байтах |
| 8 | перевод байтов в биты |

## SerfSimulator / Gossip

В классе `SerfSimulator` реализован Gossip-подход.

Каждый живой узел:

1. случайно проверяет один узел;
2. если обнаруживает отказ, сохраняет информацию о нём;
3. передаёт известную информацию нескольким случайным соседям.

Количество соседей задаётся параметром `fanout`.
