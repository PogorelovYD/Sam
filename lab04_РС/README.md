## 🎯 Цель работы

Целью лабораторной работы является разработка распределённой системы, обеспечивающей защищённую передачу данных с использованием взаимной аутентификации mTLS и симметричного шифрования.

Также необходимо продемонстрировать механизм отказоустойчивости через автоматическое переключение запросов между серверными узлами при недоступности основного сервера.

---

## 📌 Задачи работы

В рамках лабораторной работы необходимо:

1. Настроить PKI и сгенерировать сертификаты X.509 для центра сертификации, сервера и клиента.
2. Реализовать HTTPS-соединения с взаимной аутентификацией mTLS.
3. Реализовать шифрование полезной нагрузки с использованием алгоритма Fernet.
4. Разработать компоненты распределённой системы:
   - сервер обработки данных;
   - клиентское приложение;
   - координатор / балансировщик нагрузки.
5. Реализовать отказоустойчивость через автоматическое переключение на резервный сервер.
6. Выполнить индивидуальное задание по варианту 16 — локализация i18n через заголовок `Accept-Language`.

# 📚 Теоретические сведения

## PKI

PKI — это инфраструктура открытых ключей.  
Она используется для создания и проверки цифровых сертификатов.

В данной работе были созданы:

- корневой сертификат центра сертификации CA;
- сертификат и ключ сервера;
- сертификат и ключ клиента.

Центр сертификации подписывает сертификаты сервера и клиента.  
Благодаря этому участники системы могут доверять друг другу.

---

## X.509 сертификаты

X.509 — это стандарт цифровых сертификатов.  
Сертификат содержит информацию о владельце, открытый ключ и подпись центра сертификации.

В работе используются следующие файлы:

| Файл | Назначение |
|---|---|
| `ca_cert.pem` | сертификат центра сертификации |
| `ca_key.pem` | закрытый ключ центра сертификации |
| `server_cert.pem` | сертификат сервера |
| `server_key.pem` | закрытый ключ сервера |
| `client_cert.pem` | сертификат клиента |
| `client_key.pem` | закрытый ключ клиента |

---

## HTTPS

HTTPS — это защищённый вариант HTTP, работающий поверх TLS.  
Он обеспечивает защищённый канал связи между клиентом и сервером.

В данной работе все компоненты взаимодействуют по HTTPS.

---

## mTLS

mTLS — это mutual TLS, то есть взаимная TLS-аутентификация.

При обычном HTTPS клиент проверяет сертификат сервера.  
При mTLS дополнительно сервер проверяет сертификат клиента.

В этой лабораторной работе:

- клиент проверяет сертификат координатора;
- координатор проверяет сертификат клиента;
- координатор проверяет сертификаты серверов;
- серверы проверяют сертификат координатора как клиента.

Это повышает безопасность системы, так как подключаться могут только участники с доверенными сертификатами.

---

## Fernet-шифрование

Fernet — это симметричное шифрование из библиотеки `cryptography`.

В работе используется общий симметричный ключ:

```text
encryption_key.txt
```

Клиент шифрует полезную нагрузку перед отправкой.  
Сервер расшифровывает сообщение, обрабатывает его, затем шифрует ответ и отправляет обратно.

Таким образом, даже внутри защищённого HTTPS-соединения полезная нагрузка дополнительно защищена.

---

## Failover

Failover — это механизм автоматического переключения на резервный узел при отказе основного.

В данной работе координатор сначала отправляет запрос на сервер `5001`.  
Если сервер `5001` недоступен, координатор автоматически перенаправляет запрос на сервер `5002`.

# 🏗 Архитектура системы

Система состоит из четырёх основных компонентов:

```text
client.py
   |
   | HTTPS + mTLS + Fernet
   ↓
coordinator.py
   |
   | HTTPS + mTLS + Fernet
   ↓
server.py 5001
server.py 5002
```

| Компонент | Назначение |
|---|---|
| `client.py` | шифрует сообщение и отправляет запрос координатору |

| `generate_key.py` | создаёт ключ Fernet |

# 🔁 Демонстрация отказоустойчивости

Для демонстрации failover был выполнен следующий сценарий:

1. запущены два сервера:
   - сервер `5001`;
   - сервер `5002`;
2. запущен координатор на порту `8000`;
3. клиент отправил запрос;
4. координатор отправил запрос на сервер `5001`;

6. клиент повторил запрос;
7. координатор обнаружил недоступность сервера `5001`;
8. координатор автоматически перенаправил запрос на сервер `5002`.

# 📌 Вывод

В ходе лабораторной работы была разработана защищённая распределённая система.

Для обеспечения доверия между компонентами была настроена PKI-инфраструктура. С помощью OpenSSL были созданы сертификаты X.509 для центра сертификации, сервера и клиента.

Передача данных выполняется по HTTPS с использованием mTLS. Это означает, что клиент и сервер взаимно проверяют сертификаты друг друга. Такой подход защищает систему от подключения недоверенных участников.

Дополнительно была реализована защита полезной нагрузки с помощью симметричного шифрования Fernet. Клиент шифрует данные перед отправкой, а сервер расшифровывает их, обрабатывает запрос и возвращает зашифрованный ответ.

Для обеспечения отказоустойчивости был реализован координатор. Он перенаправляет запросы на доступный сервер. Если основной сервер `5001` недоступен, координатор автоматически выполняет переключение на резервный сервер `5002`.

В рамках индивидуального задания варианта 16 была реализована локализация ответов через заголовок `Accept-Language`. Сервер возвращает ответы на русском, английском или испанском языке.

Лабораторная работа выполнена успешно.
